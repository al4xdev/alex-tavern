## Why this article exists

The pre-1.0 pass produced more measured findings in one day than the previous
week of reading did, and several of them contradicted what reading the code had
suggested. Three contradicted *me*, after I had already written the wrong
conclusion down.

This is the running log of those measurements: what was asked, what the decision
rule was **before** the runs, what came back, and what shipped. It is
append-only. An entry that a later entry overturns keeps its original text with
the correction underneath, because the wrong first answer is usually the part
worth reading.

Two disciplines are load-bearing here and both were learned the hard way today:

1. **Register the decision rule before the first call.** Otherwise the rule
   moves to fit the data.
2. **Measure the instrument before trusting it.** A gate built on an unvalidated
   metric produced a false failure (entry 2) and a false negative (entry 5).

## Entry 1 — Director rule 5, the operator vocabulary (task 57)

**Question.** The Director's routing rule named "the player". Rewriting it
blind risked the response rate the rule was added to protect.

**Rule, registered first.** Ship the blind wording only if, over 4 runs per
variant on a recorded turn-1 payload, it produces a non-empty `next_speakers` at
least as often as the current one and never routes to the controlled character.

**Result.**

| Variant | Empty queues | `next_speakers` per run |
|---|---:|---|
| current (names the operator) | 0/4 | `[C2]`, `[C2,C3]`, `[C2]`, `[C2]` |
| blind (shipped) | 0/4 | `[C2,C3]`, `[C2]`, `[C2]`, `[C2,C3,C4]` |

Neither routed to C1. Shipped as measured. Honest note: the blind variant picked
more speakers on average (1.75 against 1.25), so longer bursts are the first
place to look if they appear.

## Entry 2 — Suggestions, and a gate I built on sand (task 55)

**Question.** Move suggestions were an omniscient Narrator call carrying every
sheet and every private thought, 42k characters for three short lines.

**Rule, registered first.** Ship only if private thoughts reach 0, distinct
options do not drop, **cross-call repetition does not get worse**, and cost
falls.

**First result (n=3): I failed my own gate** and wrote it up as a failure.

| Metric | omniscient | in-character |
|---|---:|---:|
| private thought lines | 9 | **0** |
| distinct options / response | 3.0 | 3.0 |
| cross-call similarity | **0.0548** | 0.0836 ❌ |
| request characters | 42 764 | **14 978** |

**Then I measured the instrument.** The same configuration, run twice, scored
0.0836 and 0.0955 — a spread of the same order as the difference I was gating
on. The baseline was no better: 0.0548 at n=3 became 0.0718 at n=10.

**Corrected result (n=10).** Most of the "failure" was measurement noise. The
remainder was real and small, and a rule requiring the three moves to engage
three different targets closed it:

| Metric | omniscient | shipped |
|---|---:|---:|
| cross-call similarity | 0.0718 | **0.0701** ✅ |
| `max_tokens` | 24 576 | **1 024** |

**What it cost to learn.** One task written up as "delivered with reservations"
that was actually passing.

## Entry 3 — The vanishing manual event (task 53)

**Question.** A queued event reached the Director prompt intact and never
appeared in the returned events. Twice, in a real session.

**What reading suggested and measuring killed.** The obvious hypothesis was
position — the block being buried. It sat at **99% of the prompt** (character
49 063 of 49 242), immediately before the routing constraint. Position was never
the variable.

**Result, 4 runs per variant on two real payloads.**

| Variant | turn 7 | turn 9 |
|---|---:|---:|
| current prompt, hint "a dragon appears out of nowhere" | 1/4 | 1/4 |
| current prompt + mandatory rule | 3/4 | 4/4 |
| current prompt, hint "a mana lamp bursts above the table" | **4/4** | — |

**The third row is the finding.** The same prompt that drops a dragon three
times in four lands a plausible event four times in four. The omission was the
model's coherence prior refusing the content, not a missing instruction. The
scenario's own power table lists "adult dragon 500 to 600", which is exactly the
coherence the dragon was fighting.

Shipped: the measured rule, plus a correction retry logged as
`guard_retry="hint_omitted"`. Detection is lexical, so a pure paraphrase reads
as a miss and costs one retry — measured at 1 run in 4 and written down rather
than assumed.

## Entry 4 — Zones: inverting a default the model kept ignoring (task 54.1)

**Question.** Walking to a table across one hall made everyone deaf: twelve
records with an empty audience, including a shouted warning that reached nobody.

**What made it interesting.** The prompt already said "a new zone starts
acoustically isolated". The model was told and ignored it — the house's own
argument for a deterministic default over a louder instruction.

**Rule, registered first.** Invert the default only if the new wording does not
seal a same-room move and seals a real departure at least as often.

**Result, 4 runs per variant on two contrasting beats.**

| Beat | old default | new default |
|---|---:|---:|
| walks across the same hall — sealed? | 0/4 (isolated silently: the bug) | 0/4 (stays audible) |
| walks out into the street — sealed? | **1/4** (leaned on the default) | **4/4** (declares it) |

Better than the hypothesis: told that sound carries, the Director started
*stating* separation every time instead of relying on a default that also fired
when nobody meant it.

## Entry 5 — A correct fix I nearly threw away (task 54.3)

**First conclusion, written down as a negative result.** Characters were
addressing someone absent. I built the obvious fix — state who is actually
present — measured it, and it came back **worse**: 2/18 ghosts against 3/18. I
reverted it and wrote up the negative result.

**The correction.** The metric was wrong, and the domain said so. Opening the
character sheets showed the "absent" name is in three characters' knowledge:
Asword's father, a canonical figure of that world. **Mentioning him is correct
characterization.** The defect is *addressing* him. My metric counted mentions
and therefore punished the right behaviour along with the wrong one.

**Re-measured against vocative position**, 8 runs per variant across the nine
recorded calls that named him:

| | baseline | with roster |
|---|---:|---:|
| addresses him ("Geralt, ...") | **13/72** | **8/72** |
| mentions without addressing | 3 | **6** |

Exactly the intended shape: they keep their world and stop talking to the
absent. One of the nine calls got worse, so this is a distribution shift, not a
switch.

**Cost of the first answer.** Reading the character sheets took two minutes and
would have prevented the whole first round.

## Entry 6 — The benchmark paying for itself, against me

One hour after entry 5 shipped, the task 29 long-horizon benchmark returned a
violation that the two runs before it had not:

```
GLOBAL-anonymous-pair-prompt / unearned_identity_familiarity
turn 9: "delegate prompt carries the signatory's never-learned name"
```

**Cause: my own roster.** It resolved names through `viewer_speaker_label`,
which falls back to the canonical name when the viewer's ledger has no entry.
That fallback is right where it was written — history only contains people who
acted in front of someone — and wrong in a roster, which names everyone present
including strangers.

**Why the test suite missed it.** My own test gave the character it tested a
ledger entry and never covered the case where one is missing — the exact hole
the fallback lived in.

Fixed by resolving through the ledger with the shared stranger reference. The
next run was clean of that rule.

## Entry 7 — Three candidate instruments for stagnation, two rejected (task 54.5)

**Question.** Ten turns of the same portal, mist and hooded figure, worded
differently each time. The lexical guards cannot see it.

**Method.** Build candidates, validate each against real sessions **before**
using any of them. Label: the audited stagnant session, plus one control I
labelled by reading its eleven narrations (it advances — a glass shatters,
stormtroopers walk in, a table is pushed).

| Candidate | stagnant | advancing | verdict |
|---|---:|---:|---|
| rolling lexical novelty | 0.499 | 0.504 | ❌ tied |
| scene-fact churn | 0.44 | 0.30 | ❌ backwards |
| **cast rotation** | **0.138** | **0.383** | ✅ correct order |

**Why the failures are the useful part.** Lexical novelty punishes consistent
atmosphere: the advancing session repeats "spice smoke" and "yellow light"
across six narrations, which is craft, not stagnation. Scene-fact churn ranked
them backwards because advance in this product lives in events and actors, not
in the fact dictionary.

**Known scope limit, found by using it.** With one controlled character and one
NPC there is never a second possible actor, so a two-character scene reports
`None` on every run. `None` means "not measurable here", never "no stagnation".
Two of the six shipped playtest scenarios are two-character and cannot exercise
it at all.

## Entry 8 — The screenplay, with n=10 instead of n=4 (task 38)

**Why it was reopened.** The standing reservation was "a coin-flip: 2 wins /
2 losses". That is n=4, which is the result pure noise produces regardless of
the true effect. The reservation was not wrong; it was unresolved.

**Method.** Two scenarios, both arms, objective harness metrics instead of a
blind critic.

| Metric | conversational ON / OFF (n=6) | large cast ON / OFF (n=4) |
|---|---|---|
| LLM calls | 60.2 / 46.0 (+31%) | 92.5 / 70.0 (+32%) |
| completion tokens | 12 528 / 9 861 (+27%) | 20 601 / 16 225 (+27%) |
| `character_action_heuristic_hits` | 3.17 / 1.17 | 8.50 / 3.50 |
| guard retries | 2.83 / 5.33 | 3.25 / 6.00 |
| narration duplicates | 5.67±8.0 / 6.33±5.0 | 4.00±4.2 / 11.50±17.1 |

**Reproducible across both scenarios**: the screenplay costs about 30% more and
raises by 2.4x the rate at which characters put physical movement inside speech
or thought — the wrong field, which the engine has `action_intent` for. It does
reduce guard retries. Narration duplicates are indistinguishable in both.

**Confound I introduced and am isolating.** The ON arm had the screenplay *and*
character alignment enabled, and alignment sends transient dramatic impulses to
characters — a very plausible cause of exactly that regression. A third arm with
alignment off is running; until it lands, the 2.4x belongs to the pair, not to
the screenplay.

## Entry 10 — The screenplay reservation, and a confound I had built myself (task 38)

**The reservation was n=4.** "A coin-flip: 2 wins / 2 losses" is the most likely
outcome of a fair coin AND of a moderate effect, so it settled nothing. It was
gated on a blind critic, which is why n stayed small.

**Rerun with the harness's objective metrics.** First ON against OFF across two
scenarios; the cost reproduced in both (+31%/+32% calls, +27%/+27% tokens), and
`character_action_heuristic_hits` — characters putting body movement inside
speech or thought — came out 2.4x higher with the screenplay in both.

**Except the ON arm had two things on.** Character alignment sends transient
dramatic impulses to characters, which is a far more plausible cause of "more
movement in the wrong field" than a screenplay the characters never see. Three
arms, n=5/4/5:

| Metric | A screenplay+align | B screenplay only | C neither |
|---|---:|---:|---:|
| `character_action_heuristic_hits` | **6.20±1.1** | 3.75±1.7 | 4.40±1.5 |
| LLM calls | 93.6 | 80.5 | **69.0** |
| completion tokens | 21 386 | 21 398 | **15 500** |

**B sits at or below C.** The regression tracks the alignment toggle, not the
screenplay. I would have blamed the wrong feature.

Limits stated rather than smoothed: the A-B gap is about 1.5 standard
deviations at n=5, and the same arm scored 8.50 in one batch and 6.20 in
another — this metric has batch variance on top of run variance.

## Entry 11 — Two bugs the measurement found on its way

Neither was caught by the suite; both were found by *running* something.

**The harness was dead from the command line.** `write_text` sat below the
`__main__` guard, so every command-line run raised `NameError` *after* finishing
all its work — six real sessions completed and reported nothing. Every harness
test imports the analysis functions directly instead of running the module. The
new test walks the AST and fails if anything is defined after the guard.

**A stylistic slip cost a whole turn.** One arm of the measurement died with:

```
ValueError: Invalid Character response after correction: Character response
places physical action in speech/thought; it belongs in action_intent
```

`act()` has three guards with the same shape — retry once, then fix the output.
Two said so in their own docstrings ("never a failed turn"): the whisper guard
redacts, the repetition guard drops a field. The physical-action guard raised.
It now moves the offending sentences into `action_intent`, and a test documents
the detector's own asymmetry (Portuguese has `inclino`, English has no `lean`)
instead of quietly widening it — widening changes how often the guard fires at
all, which is a measured decision.

## Entry 12 — A beat that never happened, committed anyway (task 45)

Task 45 shipped with "smoke HTTP real" open. Writing it found a defect on the
first run, reproduced from a live session (`ce70b997`, turn 4):

```
turn 3  next=['C1']  event: "Lyra asks lightly, 'Why do you ask, Thorn?...'"
turn 4  next=['C1']  event: "Why do you ask, Thorn? Thinking of buying it?"
```

Turn 4's only event repeats turn 3's, so the burst's anti-repetition filter
empties it; with no events a multi-beat step deliberately narrates nothing; the
queue is the controlled character, whom the runner never voices. **The beat then
committed anyway** — burning a turn number, a clock tick and a revision with
zero records.

Not cosmetic: `_next_turn_number` reads the last RECORD's number, so the burned
number is handed out again and two beats share one turn — which undo then pops
together, breaking the contract the feature rests on.

**The first fix was too aggressive** and broke an existing test: a time-skip beat
legitimately advances the clock without a record of its own. The guard is now
narrow — no record AND no scene update AND no time compression.

Of the smoke's three initial failures, one was my own naive assertion: undo
restores the beat's snapshot, which already accounts for time compression, so
the clock does not rewind by exactly one. Corrected in the smoke, not in the
engine.

## Entry 13 — A blind review, and a mechanism I nearly published wrong (task 26)

**The lane had been open for weeks** asking for "new event-level evidence". Both
acceptance criteria were finally run instead of deferred.

**Criterion 1 passes.** Duplicate thoughts: zero in 13 of 14 runs. Narration
duplicates: median 1, against a historical 0/2/6/15. Not a controlled A/B —
same counter, same harness, different scenario and n. Said so rather than
implied otherwise.

**Criterion 2 fails.** A real blind review — reviewer told nothing about the
project, the arm, or what we expected, and explicitly told an empty report is
valid — over 15 sessions:

| | |
|---|---:|
| with a staging jump | **13/15** (18 instances) |
| with a reader-visible repeat | 7/15 |
| unreadable responses | 0 |

**All 36 cited staging passages are in narration, none in speech.** The layer is
the prose renderer.

**The mechanism I nearly published.** My first explanation was that a flat scene
returns an empty STAGING block, so the renderer does not know who is where. It
is testable, so I tested it:

| | with a staging jump |
|---|---|
| flat scene (no STAGING block) | 2/3 |
| zoned scene (**with** the block) | **11/12** |

Having the information does not prevent it. The explanation was wrong and was
one paragraph from being written down as fact.

**What the 18 instances actually are**, read one by one:

```
"Thorn steps into the watchtower for the second time, having already done so"
"Town watch arrives at the tavern entrance in line 7, then arrives again in 19"
"The hooded figure retreats into the passage in 16, then retreats again in 19"
"The kitchen door swings ajar in 11 and swings open again in 13, never closed"
```

One class: **a transition re-enacted**. Prose narrates an arrival, a retreat or
an opening the transcript already completed, in fresh words. That is exactly why
no guard sees it — the whole-narration and per-sentence guards compare text, and
the burst dedupe only compares within one burst.

Sibling of entry 7's stagnation finding, same root: the guards are lexical, the
defect is at event level.

## Entry 15 — The token the summary turned into a person (task 36)

Task 36 asked for something specific: *"Prose renderer receives only validated
public facts: no thoughts, no sheets, no IDs, no roteiro material in its request
(assertable from debug.jsonl)."* Assertable from the debug log, not from a
builder test. I ran it against 17 real sessions.

Thoughts: 0. Character sheets: 0. Roteiro material: 0 across 1182 non-Director
calls. IDs: **4968**.

### The negative control, again

My first scan filtered by `agent not in ("character", "prose", ...)`. The real
agent names in the log are `character:Lyra`, `perspective:init:C2`,
`summarizer:world`, `suggest_moves` — so that filter matched only `prose`, and
the reassuring zero I nearly published covered 239 calls instead of 1182.

What exposed it was pointing the same scan at the Director and *requiring* it to
find the text. It found 444 hits in 10/10 sessions. This is the second time
tonight the control saved the conclusion, and the rule has earned its place: a
scan that reports absence needs a target where presence is mandatory, in the
same run.

### Why an id in a prompt is not a cosmetic problem

`speaker_label` translates only the internal `Player` marker. Every other
speaker comes back as the stored token, and for a character that token is its
id. The Director doesn't care — its prompt carries an `ID=C2 | NAME=Marta`
roster, and 330/330 real Director calls resolved. Prose and the Summarizer build
no such mapping.

Prose paid once: `"raising his free hand in a short, decisive motion toward
C2"`, persisted and shown before compaction evicted it.

The Summarizer paid permanently. 11 of the story summaries came back carrying
the token, and the summary is the durable memory every later prompt reads:

> "A group (Thorn, Lyra, and a talkative companion **called C2**) gathers in a
> rainy tavern…"
>
> "Lyra **(C2)** is a spellcaster… A hooded stranger **(C2)** earlier…"

The first invented a third cast member. The second collapsed two different
people into one token. From then on, the session's own memory was wrong about
who exists — and every Director, prose and character prompt read that memory.

### The measurement

Pre-registered rule, written before the run: the names arm wins only if it
produces strictly fewer summaries containing a raw id **and** no summary loses a
character the ids arm was naming. 15 real summarizer payloads, 2 repetitions,
both arms.

| arm | summaries with a raw id | occurrences | characters named |
|---|---|---|---|
| ids (shipped until today) | 10/30 | 20 | 2/2 |
| names (fix) | **0/30** | **0** | 2/2 |

Both halves pass. `display_name()` now resolves a speaker all the way to a name,
and prose and the summarizer use it.

### The third path, and the repair I nearly got wrong

Two character prompts also carried an id, from a source neither fix touched:
`context_for_character` is free prose the *Director* writes, and the Director
thinks in ids. `project_text_for_viewer` rewrote every id it held a `PersonView`
for — but a viewer holds no view of themselves, so their own id was the single
token that could never be replaced. Lyra read *"a sharp, scraping sound comes
from the drain grate near C2's feet"*.

The obvious repair — resolve every remaining id to its canonical name — would
have re-created the exact regression the roster work produced earlier tonight:
handing out acquaintance nobody earned. The projection now sweeps what the
ledger did not cover with the distinction that matters: the viewer's own id
becomes their own name, anyone else's becomes the anonymous reference. **An id
is not an introduction.**

### What this says about the criterion

Task 36 closed with this box unchecked and the feature shipped. The box was not
decoration — the thing it asked for was real, cheap to run, and found a defect
that had been corrupting session memory in production. The suite stayed green
before *and* after the fix, so no amount of running tests would have surfaced
it. Only reading what the system actually sent did.

## Entry 16 — A critical review of the night, and what it broke

The owner asked for an adversarial review of the previous entries' work, with no
context handed to the reviewer. It found five real defects. Recording them here
because a measurement log that only records findings, and not the times the
instrument was wrong, is advertising.

### The tests that could not fail

**Two of the three new whisper tests were vacuous.** They located the composer's
submit path by anchoring on `state.lastTurnFailed = false;\n state.canUndo = true;`
— a statement pair that occurs **twice**, and the first hit is `skipTurn`, not
`sendTurn`. `skipTurn` never touches `inputSpeech/Thought/Action` and cannot
contain `clearWhisperSelection`, so "the inputs are not cleared on failure" and
"the whisper selection survives" were true by construction.

Worse, the slice ran to `} finally {` — *excluding* the finally block. The
docstring named "a later edit moving these resets into a `finally`" as the exact
threat, and the test could not see a finally block at all.

Both are fixed, and this time I proved it by mutation: moving
`clearWhisperSelection()` into `sendTurn`'s finally now fails
`test_the_whisper_selection_survives_a_failure`. My first attempt at that
mutation patched `skipTurn`'s finally and passed — the same off-by-one-function
error, twice in ten minutes.

**A thought-containment test was a tautology.** It built the summarizer's input
by filtering thoughts out of the history itself, then asserted the thought was
absent. It now runs the production chain: `capture_memory` first, then build the
revision prompt from whatever capture produced.

### The metric I put in a commit message measured nothing

Task 28's acceptance tool reported "the real Director proposed an NPC in 0 of 5
forced rounds", and both the commit and the plan doc led with it as the reason a
live run beats a unit test.

`record["response"]` is stored as a JSON **string**. `json.dumps()` on a string
escapes it, so the predicate `'"C2"' in raw` searched for `"C2"` inside
`\"C2\"` and could never match. Pinned at 0 forever. And had I fixed the
escaping, it would have matched every turn regardless of routing, because it
searched the whole response and `scene_blocking.character_zones` lists every
character every turn.

It now parses the response and reads `next_speakers` — the only field that means
"the Director wants this character to act" — and the script asserts that it
parsed something, so a future serialization change fails loudly instead of
reporting a comfortable zero. Re-run: still 0/5, now earned.

**A second check in the same tool could not fail either.** It flagged NPC records
"not staged by the Director" via `not record.get("audience_origin")`, but that
field defaults to `"whisper"` and is always serialized. The discriminator that
works is the debug log: a character only speaks when it was called.

### The absolute claim

The fix commit was titled *"never hand a prompt an internal id it cannot
resolve"*. Live `drive:event_seed` prompts, logged after the fix, read:

```
RECENT EVENTS (oldest to newest):
  C2: Bem, parece que nossa reputacao nos precede.
  Thorn: ...
```

One cast, two labelling systems in one list — the same shape as the summarizer
defect the fix was about. It is a documented, curl-validated difference
(`recent_event_lines(resolve_names=False)`), so changing it is a prompt
experiment under AGENTS.md §6 and not a tidy-up. But "never" was wrong, and the
residue is now pinned by `TestTheResidueThisFixDidNotCover` so the next person
finds it as a fact instead of a surprise.

### The side effect that outlived the run

Two acceptance scripts `PUT /config` and exited without restoring. The server
was left on `compaction_keep_recent_turns=2` and `autonomous_burst_max_beats=1`
— so every session played afterwards compacted almost every turn, including any
measurement taken later. Restored, and both scripts now save the config and put
it back.

### What holds

`display_name`, the `project_text_for_viewer` sweep, the crash-mid-burst test and
the rapport-accumulation test all survived the review, the last two verified by
the reviewer as genuinely failing when the behaviour is reverted.

### The pattern, stated plainly

Every defect above is the same one: **a check that passes for a reason other
than the one claimed.** An anchor that matched the wrong function, a predicate
that matched nothing, a field that is always set, an input filtered by the test
itself. Entry 15 ended with "a scan that reports absence needs a target where
presence is mandatory". That rule was written for scans and applied to none of
these tests. It generalises: *every* green assertion needs a demonstration that
it can go red — and the demonstration has to be run, not imagined.

## Entry 17 — Two lessons about the instrument, not the system

### Measurements that only the author can verify are reports, not evidence

The critical review pointed out that most numbers in entries 1-16 cite sessions
written to a temporary directory. The session behind three closed criteria
(`8484d749`) does not exist anywhere a reader can reach. The method is described
well enough to redo, but "described well enough to redo" is not the same as
"verifiable", and closing an acceptance criterion whose whole point was
*assertable from debug.jsonl* on an unreachable artifact is weaker than it looked
while typing it.

Tasks 34, 35 and 39 now carry that caveat explicitly. The durable fix is the one
already used for tasks 28, 36 and 45: a script in `tools/acceptance/` that anyone
can run, whose output is the evidence. A number in prose is a claim; a committed
script that reproduces it is a proof.

### The harness can fail in a way that looks like a result

Setting up the drive A/B, the first two attempts returned empty responses and I
read them as noise from the model. They were not. Production sends
`thinking_enabled: false`; my hand-rolled POST omitted it, so a reasoning model
spent the whole 256-token budget on `reasoning_content` and returned an empty
`content`. The fix was not a bigger budget — it was calling `call_agent`, the
same path the product uses, and passing the config through `resolve_active_config`
so the transport is identical.

Two failures in a row that presented as data. The rule that generalises from
entries 15 and 16 — *a green result needs a demonstration it can go red* — has a
twin for measurement: **an arm that produces no output is a broken instrument
until proven otherwise, never a finding about the arm.** The cheap check is to
run the production call path instead of reimplementing it.

## Entry 18 — The drive/watcher label experiment: the rule said no

Entry 16 ended with a residue: `drive` and `watcher` prompts label characters by
internal ID while the same list resolves the controlled character to a name, so
one cast arrives under two naming systems. That is the shape of the defect that
corrupted eleven story summaries, and the seed produced here becomes the
Director's `narrator_hint` — text the Director is instructed to materialise.

Rule fixed before the run: the NAMES arm wins only if it (1) produces strictly
fewer seeds containing a raw id **and** (2) does not lose grounding, measured as
`source_thread` quoting something literally present in the context it was given.

| n=80 per arm | seeds with a raw id | grounded |
|---|---|---|
| ids (shipped) | 5/80 | 74/80 (92%) |
| names | **0/80** | 70/80 (88%) |

Criterion 1 is decisive. **Criterion 2 fails**, at n=32 (31/32 vs 30/32) and
again at n=80.

> **Correction, appended 2026-07-27 after an independent review.** The sentence
> that stood here read: *"with the gap widening rather than shrinking — which is
> what separates a real effect from noise."* **That inference is invalid.** One
> defect out of 32 versus five out of 80 in underpowered samples is coin-flipping,
> not evidence of a widening effect. Run properly, the two criteria are:
>
> | | ids | names | p (two-sided) |
> |---|---|---|---|
> | grounding | 74/80 | 70/80 | **0.43** |
> | raw id | 5/80 | 0/80 | **0.059** (one-sided 0.029) |
>
> So the criterion that VETOED the change carries p = 0.43 and the criterion that
> approved it carries p = 0.03. I treated the noise as a veto and the signal as
> supporting detail, then wrote a sentence dressing the noise up as an effect.
> The verdict below is left standing as the historical record of what was decided
> and why; the reasoning that produced it does not survive.

**Verdict at the time: the default does not change.** Not because the leak is
acceptable, but because the rule was written before the data and the data did not
clear it. Rewriting the rule after seeing the numbers is the exact failure
documented in entry 2 (task 55).

That protection was right and is worth keeping. But the same review drew a
distinction I did not have, and it is sharper than mine: **"must not drop", as a
strict inequality over a stochastic binary rate with no noise floor, rejects
roughly half the time even when the two arms are identical.** That flaw is
readable in the text of the rule *before any run*. Naming it is not moving the
goalposts after the fact — it is noticing that the goalposts were crooked at
pre-registration. Guarding against the first failure does not excuse the second.

The harm is real and now documented rather than hypothetical. Two of the five
polluted seeds:

> "The medallion on **C2's** chest suddenly glows with a faint blue light…"
>
> "**C2**: Dorothy steps forward and says: 'We must examine that cipher…'"

The first would be handed to the Director as the hint to dramatise.

### The caveat that should shape the re-run

The grounding metric rewards a `source_thread` that quotes the context verbatim.
The ID arm quotes more literally, because `C2:` reads as a record label and gets
copied wholesale; the names arm paraphrases more. So the metric may be measuring
**quotation**, not grounding — which would favour the shipped arm by
construction, exactly the class of error entry 15 caught (mentions vs vocative
position) and entry 16 caught again (surface vs mechanism).

I am not using that suspicion to overturn the verdict: suspecting your own metric
after it gives an unwanted answer is not evidence. It is the design note for
whoever runs it next, and the instrument it calls for is a blind judge on
grounding, not a four-word window.

Until then: the residue stays, `TestTheResidueThisFixDidNotCover` keeps it from
being forgotten, and the reason it stays is a measurement rather than an opinion.

## Entry 19 — Three criteria that were unrunnable, not unrun

Closing the last real-run criteria produced the same discovery three times: they
had never been executed because **the thing they needed did not exist**.

- Task 32 wanted a run with two natural-routing probes. No scenario in
  `tools/playtests/` contained a `routing_check` event.
- Task 33 wanted several skip turns against a scheduler-disabled control. No
  scenario contained a single skip turn, and the scheduler only exists on idle
  turns.
- Task 31 wanted three repetitions of an existing scenario. That one only needed
  running, and it passed: 3/3 completed, zero lost to unrecoverable JSON.

Two of three unchecked boxes were not laziness or oversight. They were criteria
written for an instrument nobody had built, and every later reader assumed the
gap was on the "someone should get around to it" pile rather than the "this
cannot be done at all" pile. A criterion that names a scenario should ship with
the scenario, or it is a wish.

### What the runs said once they could happen

**Routing (32): 3 of 5 valid probes reached the addressed character.** When it
fails, the Director answers with narration and routes to nobody, even though the
line names the person and asks them a direct question. Two executions disagreed
on the same probe, so the variance is the size of the effect and the number is
recorded as 3/5 rather than re-rolled until it flattered.

**Drive (33): the scheduler fired twice with the flag on and zero times with it
off**, and both seeds reached the scene — one re-enacted in fresh words rather
than copied, which is the desired behaviour and, per task 26, the class no
lexical guard can see.

**Retry policy (31): nine schema violations, nine recoveries.** The Director sent
booleans where the schema wants string-or-null six times, always in
`scene_update` keys it invented itself. Before task 31 each of those was a lost
turn; here none reached the player.

### And one thing the instrument got wrong

Two of 31's three runs were scored as failures for "whispered secrets leaked",
citing the tokens `onde` and `cabeça` — "where" and "head". The detector accepts
any token of four or more characters near the whisper anchor, and in Portuguese
that is the scene's ordinary furniture.

Not fixed today, deliberately: that detector is the oracle the xfailed3 `secret`
family depends on, and recalibrating it without first measuring its false
positive rate would trade one bias for another. It is the next thing to measure,
which is a better place to leave it than a silent tweak.

## Entry 20 — Four leaks in the agency guarantee, and why my own guard missed them

An external review of the codebase found four places where the guarantee that no
agent learns a human drives one of the characters was broken. I verified all
four against the code. Three were unambiguous.

### Two in a shipped scenario

`turma-dos-portais-pt.json` said, in Link's **personality**:

> "As escolhas, pensamentos atuais e coragem de Link pertencem sempre ao humano."

and in the directives, under a heading named `PORTAIS DE LINK E AGÊNCIA`:

> "nenhum agente escolhe fala, pensamento, coragem [...] por ele"

Both name an outside owner of one character's inner life. Both reach the
Director, and the personality field also reaches Character, Perspective and
Alignment when someone else is controlled — where it is also simply **false**.

### Two in the Director prompt

`return_control` was described as answering for "the protagonist of the **last
input**". *Input* has no referent inside the story.

The routing constraint said "Do not include C1 [...]; they just spoke or
passed". True on beat one of a burst; **false on beat two**, where the same id
stays excluded and the reason no longer holds. A model resolving that
contradiction has only one explanation available.

### The part that is mine

Task 57 closed declaring this family clean, on a detector I wrote. Run against
that scenario, the detector fires on **nothing**. Two independent causes:

- every pattern named the operator with a **noun** — "the player", "controlado
  pelo jogador". These leaks use a **verb** ("pertencem ao humano") or negate the
  agents ("nenhum agente escolhe"). I wrote the list against the vocabulary I
  expected, not the vocabulary a scenario author reaches for.
- `test_builtin_scenarios_carry_no_operator_ontology` read **only**
  `narrator_directives`. The worse leak sat in `characters.C1.mind.personality`,
  a field it never opened. A scenario reaches the prompts through its cast sheets
  as much as through its directives.

This is the pattern from entries 15, 16 and 19 landing in the most expensive
place available: **a green from a check that could not go red.** The rule has
been stated three times in this log and still did not stop me from closing a
confidentiality task on a guard with a blind spot in both dimensions — what it
looks for, and where it looks.

### What shipped

Detector widened to verb and negation forms, the built-in test now sweeps every
string in every field, the scenario was rewritten blind, and the two Director
lines were reworded and then **measured** rather than assumed:

| 3 real payloads, 5 runs/arm | selected the excluded id | empty queue |
|---|---|---|
| current | 0 | 2 |
| new wording | 0 | **0** |

Approved by the pre-registered rule. The improvement is mechanically plausible
rather than surprising: the old line asked the model not to do something, the new
one asks it to do something.

And the harness caught me twice more while I built it. Its payloads first came
from a temp directory the OS reaped between runs — the exact
non-reproducibility entry 17 is about. Then it matched only the OLD wording, so
against freshly generated sessions it found zero payloads; one step further and
it would have measured the new variant against itself and reported a tie.

## Entry 21 — The invariant that a measurement was allowed to veto

Entry 18 closed the drive/watcher label question with "the rule said no". Two
things were wrong with that, and an independent review found both.

**The statistics were backwards.** Grounding, the criterion that vetoed the
change, is p = 0.43. Raw ids, the criterion that approved it, is p = 0.03. I
treated the noise as a veto and the signal as supporting detail, and then wrote
a sentence — "the gap widened rather than shrinking, which is what separates a
real effect from noise" — that dressed the noise up as an effect. One defect in
32 versus five in 80 is coin-flipping. That sentence is now corrected in place.

**The rule was malformed at pre-registration, and that is a different sin from
the one I was guarding against.** I refused to rewrite the rule after seeing the
data, which was right and stays right. But "must not drop", as a strict
inequality over a stochastic binary rate with no noise floor, rejects roughly
half the time even when the two arms are identical. That is readable in the
rule's own text *before any run*. Guarding against moving the goalposts does not
excuse setting them crooked.

### The error under both of those

I had classified the finding as ID hygiene. It was an agency leak, and the code
says so plainly:

```python
canonical = controlled if speaker == "Player" else speaker
```

The set of characters rendered by name was **exactly**
`{player.controlled_character_id}`. The prompt did not hint at that field, it
computed it — one hour after I had shipped a Director fix whose whole argument
was that singling out one id IS the leak, with no operator vocabulary anywhere.
I applied the principle to the Director and failed to apply it to the function I
was measuring at the same time.

That is why the measurement went wrong in the first place: **I measured the
downstream symptom (does an id reach the output?) instead of the invariant (is
one character formatted unlike the others?).** A well-run experiment on the wrong
variable still answers the wrong question.

### The rule that comes out of this

An invariant is not a trade-off. When a finding falls under `AGENTS.md` §3, the
experiment decides the **shape** of the fix, never whether one happens. That is
now written into §3 itself, along with the statement that structural markers —
label, order, an extra field, a named exclusion — leak exactly as much as the
word "player" would.

### What shipped

`resolve_names` was **removed**, not defaulted safer: its off position broke an
invariant, and keeping the flag leaves the unsafe path one keyword away. A
structural guard now exists (`singled_out_speakers`), because every pattern in
the contract file is lexical and none of them could ever see a leak encoded in
formatting. The pinning test was rewritten to assert the property that matters —
no speaker formatted unlike another — instead of "names appear", which would
have passed on the old behaviour too.

### The part worth keeping

The neutral hand-off worked. The task document was written to withhold the first
session's preference so a second analysis could start clean; it did, reached the
same reading independently, and corrected two errors in the first session's
reasoning on the way. Agreement reached *after* independent analysis is evidence.
Agreement produced by handing over a conclusion is not.
