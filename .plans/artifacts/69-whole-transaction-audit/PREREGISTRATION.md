# Whole-transaction semantic audit, before fresh calls

The controlled converter's twenty high-thinking final outputs passed its local
source/operation screen, but a separately constructed other-text opening/
crossing bypass passed mechanical validation. This screen tests whether a
model auditor diagnoses complete claim coverage before rendering, not whether
it establishes a deterministic narrative guarantee or admits runtime integration.

Nine frozen packets reuse controlled sources/outputs, never owner-play sessions:
1 clean blocked attempt plus continuing closed-state observation (accept);
2 append untyped blue opening AND Téo crossing to that blocked transaction
(reject, must diagnose BOTH physical claims);
3 append fresh blue closure while already closed (reject);
4 legal ajar->open, guard entry/collapse after opening, order/shield (accept);
5 supported new closed->open reopening then Téo crossing (accept);
6 hide a green opening in the blue-opening cause (reject, green claim required);
7 reorder causally independent green opening/blue blocked attempt (accept);
8 replace supported full reopening/crossing by ajar/blocked (reject, must identify
loss of the supported passable opening/successful crossing);
9 an unregistered-or-tracked door explicitly not identifiable from supplied
source (uncertain, no invented binding to blue or green).

The auditor receives whole source and transaction, not expected label, previous
judgments or mechanical pass. Schema orders issues and uncertainties before
can_render. Local descriptions tie every boolean outcome to those fields:
true means both empty and transaction may proceed; false means an identified
problem or unresolved identity, so it may not proceed. Issues carry step_number
(1..N, or 0 for a source event wholly absent), category, literal source and
transaction quotes and explanation. Uncertainty has literal ambiguous quote.
Quote checks prove provenance, not semantic correctness. Quotes may copy decoded
text/field values or an exact JSON span from the supplied source/addressed step.
For step_number=0, transaction_quote is '' because there is no transaction
passage to quote; source_quote remains literal and nonempty. Classification
is accept when both arrays are empty, reject when issues is nonempty, otherwise
uncertain when uncertainties is nonempty. An issue plus uncertainty is reject
with an unresolved additional question, not an ambiguous boolean contract.
Continuing state is not a new transition; supporting reference to the SAME typed opening is not
an additional untyped change. Source proposed_beat is uncommitted and may need
correction; do not demand preservation of impossible proposal outcomes.

Freeze script/protocol/source hashes/schema/all exact requests before calls.
DeepSeek V4 Flash high thinking, max8192, four fresh logical calls per packet:
36 calls via actual client/adapter over curl, maximum three attempts under
the existing production policy: JSON parsing/schema failures, response-envelope
failures and retryable HTTP/transport errors may retry; definitive HTTP client
errors fail fast. Quote/decision/semantic failures NEVER trigger a retry.
Preserve raw requests/envelopes, schema errors/retries, transport failures,
terminal results, response IDs/reasoning/debug in isolated /tmp and ignored
artifacts. No replacement calls or semantic feedback repairs. Report first-
attempt and terminal acceptance separately per packet, including failed attempts.

Rule: all 36 logical calls must terminate locally schema-valid with decision/
arrays consistent, and quoted text literal in supplied source/transaction.
Every final response must match the frozen accept/reject/uncertain expectation.
On rejected cases, all specified independent claims must be diagnosed; a generic
false flag that misses the second crossing/opening does not pass. A blinded
Gemini text reader checks complete findings against literal source, with no
expected labels or supplied verdicts. Main reading checks objections; unresolved
material uncertainty gets a second isolated reading of EXISTING material and
then stops the candidate if unresolved. Any missing/misbound/unsupported finding,
false veto or invalid/exhausted final response stops this exact auditor.

A pass is local diagnosis evidence only, not autonomous repair, full Director
binding, dynamic registration, other physical dimensions, per-viewer/prose
fidelity, consecutive persisted Runner submissions or Task69 closure. An auditor
can itself miss claims, so it cannot replace the store's typed deterministic
checks. We will not call it a deterministic closed-transition guarantee.
