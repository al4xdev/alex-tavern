# T38 closed-packet constructive prose test, before authoring

The preceding realizer [screen](T38-PROGRAM-STYLE-CROSS-RESULT.md) failed its
technical and content gates. This **one-shot constructive test** asks a
different, narrower question: do the exact S and L scene/program packets
contain enough authorized material for a skilled, isolated fiction writer
to produce finished RPG narration without silently adding events? It is
not a repeat of the stochastic realizer, not a model reliability test, and
cannot certify a runtime architecture.

The sole author input is
[`t38-constructive-author-packet.json`](t38-constructive-author-packet.json),
SHA-256 `45e1b9eee08daee48a1f989a71256c09d8bad33618bfa9c92c16d036739a497c`.
It is extracted from the frozen cross-screen manifest and contains the same
static scene glossary and the S and L programs. The writer receives **no**
archived scene prose, previous model outputs, style reference, code, or
result. It writes one Portuguese narration for S and one for L, and a
separate list of any additional information it felt it needed. It must
not create dialogue or turn an existing state into a new event. The packet
itself, the author request and its full response will be archived before
either narration is judged.

Permitted realization: syntax, pacing, imagery and sensory consequences
directly implied by a listed material or event. In L, an automatic metal
closure may have an immediate audible impact; in S, no fresh closure sound
is available. A crossing can produce ordinary footfall; a blocked attempt
can be described without completing passage. Metaphor is permitted only if
it does not imply a new actor, object, change of aperture, crossing, cause,
private feeling or offstage perception. New gestures, extra actions and
ambient facts not in the packet must be listed as requested additions,
not smuggled into the narration.

Before reading the authored text, freeze this decision rule: an independent
continuity reader, blind to previous screen outputs, marks for each
sentence which program/static fact or direct sensory consequence supports
it, and flags additions, omitted events and wrong order. Another isolated
fiction reader judges each narration as a ready RPG scene rather than a
status list. **Constructive local pass requires both S and L** to satisfy
their physical program with no unsupported addition and the fiction reader
to accept both as finished prose. Disagreement is recorded and no votes
are averaged. If either fails, the attempt has not demonstrated packet
sufficiency; one writer's failure does **not** prove such prose impossible.
If both pass, the authored texts are existence examples for these two
manually curated packets only. The failed realizer remains failed; the
result merely clarifies whether to work on packet representation or on
realization next. No code or runtime state is changed by this screen.
