# Blue-gate closure extraction screen: local candidate stopped

The [pre-registered](BLUE-GATE-EXTRACTION-PREREGISTRATION.md) T36–T39 fixture **failed its semantic gate**, which required all four outputs on every turn to match both frozen labels. All sixteen direct curl calls returned HTTP 200, unique provider response IDs and locally schema-valid JSON; no call was replaced. The four frozen requests, source/script/preregistration hashes, raw envelopes and parsed results are preserved in `blue-gate-extraction-manifest.json` and `blue-gate-extraction-runs/`. This is a local screen of four proposals in **one archived session**, not sixteen independent story cases or an estimate of model reliability. `aperture` is the discrete `ajar`/`closed` property: narrowing a still passable gap does not reach the fixed `closed` candidate. `uncertain` authorizes no transition but did not count as a correct label on these pre-labeled fixtures.

| Turn | Frozen expected `aperture / repeated_closure` | Four returned pairs |
| --- | --- | --- |
| T36 | `no_change / false` | `change / false`; `no_change / false`; `uncertain / false` twice |
| T37 | `change / false` | `change / false` four times |
| T38 | `no_change / true` | `no_change / false` three times; `change / true` once |
| T39 | `no_change / false` | `no_change / false` four times |

I reread the source sequence against every label. T36 leaves a narrow usable gap (`quase fechado, fresta apertada, rangendo`), so the fixed discrete `closed` candidate has not been reached; one `change` and two `uncertain` labels do not match the registered fixture decision. This does not mean the gate's width was physically static. T37's time-skip summary closes the gate and update records `fechado`; all four labels match. T38 asserts another closing action after T37's already completed closure, while the current fixture and same-turn update both say `closed`; three calls did not flag `repeated_closure`, and the fourth returned `change` despite the prompt rule that a candidate equal to current cannot be a transition. T39 only observes sealed gates without a new closing action, so its four `false` labels are the matched negative control. T38 also restages character crossing, a separate continuity issue not scored as aperture.

The all-valid prerequisite passed, so this is a **semantic failure** under the frozen rule, not a technically incomplete run. The result stops this extraction shape before any producer or runtime integration. It does not show why the model missed T38 or whether a different prompt, schema, request order or model would succeed. The earlier hall-gate V2 screen passed a different local fixture but did not include an explicit already-completed closure plus same-state negative control; its narrow result remains intact. A repair experiment for T37→T38 needs its own pre-registration and must inspect both revised accepted events and final prose, because simply storing no aperture transition does not by itself remove a repeated closure from narration.
