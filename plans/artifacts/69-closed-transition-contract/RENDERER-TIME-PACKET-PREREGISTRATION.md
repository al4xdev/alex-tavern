# Renderer time-packet A/B, frozen before provider calls

The V2 transaction screen yielded valid typed physical events but one readable
`open_cross` prose invented a gate opening. This test asks whether a coherent
renderer input contract can keep the *same* confirmed events in their temporal
order without inventing aperture or ice changes. It does not identify which
prompt clause causes an error, and it does not test a production integration.

Use exactly the four V2 `*-1` Director results and their derived confirmed
events. No new Director call or event rewriting. A is each saved V2 prose
request, unchanged. B uses the same model, adapter JSON instruction, settings,
transcript and events. It changes a **bundle** of conflicting renderer inputs:
the event actor's visible appearance is included; the final-state roster rule
permits authorized events of this beat while forbidding unconfirmed subsequent
actions; the prompt states fixture-derived BEFORE and AFTER aperture, seal and
Liora position; confirmed continuing conditions may be narrated; the 150-word
minimum is removed. The before/after states are model-facing public names, no
internal IDs. B may narrate Liora crossing from the salon viewpoint, but may
not follow her actions inside an acoustically isolated tunnel afterward.

Freeze script hash, this protocol, cases, four source results, the eight exact
adapter-built request bodies and the 32 dispatch-label hashes (four repeats
of each body) in a manifest before dispatch.
Then run four fresh direct DeepSeek curl calls per case and arm (32 total),
with no replacement calls. Preserve HTTP, raw response, parsed output and
response IDs. Check each against the actual narration schema. If any B call
fails the technical contract, the candidate fails after the already-dispatched
batch completes; still read valid individual
outputs with that limitation explicit.

Give an independent reader the complete fixture and prose, blinded to arm.
The reader judges each output separately for (1) confirmed beat conveyed,
(2) physical sequence and final-position fidelity, including new gate/ice
history, (3) leakage or actions after departure, and (4) story-prose quality.
Request literal supporting excerpts and distinguish factual contradictions,
unsupported backstory, omissions and ambiguous imagery. Resolve disputed
readings against the text, not a keyword count. B passes this local screen
only if **all 16 B outputs** are schema valid, convey their confirmed beat,
remain physically aligned, and are judged usable as story prose. Any clear B
failure stops the candidate. Compare A descriptively: if A has no relevant
defect, claim no improvement. Even a B pass permits only a subsequent archived
scene test, not runtime wiring or a reliability estimate.
