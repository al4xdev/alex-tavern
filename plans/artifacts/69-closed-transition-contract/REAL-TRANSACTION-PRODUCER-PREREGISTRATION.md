# Real-source physical transaction producer screen, frozen before calls

This is a test of **model authorship of one ordered physical transaction**,
not of renderer quality or production integration. The persistent impasse is
that separate free prose and transition annotations can disagree. The typed
store already rejects illegal edges; no model producer currently feeds it.

Two archived real Director requests and their accepted drafts are selected:

* **F, blue T38:** `p1-archive/null-P1-r1/7fd84e9a` T38. At the committed
  start, the blue gate is closed, five blue-team members are already in the
  tunnel, and Téo is in the hall. His final declared advance through the
  fresta is an attempt. The accepted proposal re-crosses the team, moves Téo
  through the closed gate and closes that gate again. Preserve the exact
  original Director **user context**, including its conflicting descriptive fact;
  supply the typed initial aperture and positions but **no manually written
  blocked-attempt diagnosis**.
* **P, main-gates T8:** `p1-archive/drive-P1-r1/5c994c42` T8. Main gates
  start ajar; an external impact opens them, and a wounded guard enters and
  collapses. This legal opening must survive. The original Director user
  context and accepted draft are frozen as source; typed initial aperture is `ajar`.

The model returns an ordered list of steps. A step is exactly one of a typed
aperture transition, a typed crossing-attempt result for a named actor, or
`other` reader-visible event content that asserts **no tracked gate aperture
change or crossing result for a tracked character**. The wounded guard in P
is not a registered character and may be described entering after the opening.
The same schema fields are present for all kinds, with
irrelevant fields empty. A transition names a public target and current/new
aperture; a crossing result names the target, actor and `blocked` or `crossed`.
The program resolves the target to a single manually seeded entity, validates
transitions and crossing against the initial typed state, derives the gate and
crossing sentences from accepted typed steps, and assembles all steps **in
their declared order**. It never copies a gate action sentence from the
rejected source draft. The model must preserve consequential non-gate events
in `other` steps, and must resolve the final attempted action when present.
`other` may report that a character speaks, but may not write or quote that
character's dialogue; dialogue remains a separate Character call.
The reader, not a keyword screen, catches any hidden gate action, omitted
consequence, invented cause or contradiction in `other` text.

Run four fresh independent chains per case. Each first call receives the
archived Director user context and accepted draft, initial typed state,
public labels, schema and this contract. The original Director system prompt
is hashed as provenance but **not sent as an instruction**: its incompatible
whole-Director response schema would conflict with the transaction schema.
If and only if deterministic validation rejects its steps, send the rejected
JSON back once with the **exact mechanical rejection** and request a full
replacement; count the first pass and final result separately. No failed call
is replaced as another sample. Use the DeepSeek adapter's JSON instruction,
the shared client's Brazilian-Portuguese/no-dash instructions and direct
`curl`. Freeze source, script, protocol and all first request bodies before
dispatch; save every request, raw envelope, response ID and validation.

The technical prerequisite is complete source capture, HTTP 200, distinct
IDs and schema-valid JSON on every dispatched call. A malformed first output
is a failed chain, not eligible for semantic retry. Mechanical rejection can
receive one retry, whose response must also pass those checks. A chain still
rejected after retry fails its final gate. No chain is replaced.

**Registered content rule, one case per source:** all four final F
transactions must leave the already closed blue gate without an unpreceded
new closure, avoid a crossing through that closure, avoid re-crossing people
already in the tunnel, and give Téo's attempt a coherent consequence without
teleporting him. An explicit newly caused reopening followed by crossing is
eligible only if its cause is in the transaction and a blind reader accepts
its causal sequence. All four final P transactions must keep the external
impact's `ajar -> open` change, the guard's entry and collapse, and the
remaining material beat without inventing a second opening. All final
transactions must be mechanically legal and their assembled text coherent in
order. A blind content reader receives shuffled source/transaction pairs and
quotes any omission, unsupported physical change, misbound target/actor or
cross-field inconsistency. **Any** final failure stops this candidate; no
semantic similarity, lexical name matching or pooled rate decides admission.

A pass would only be a local producer/repair signal on one defective beat and
one legal control. It would not establish reliability, dynamic entity
creation, the kennel gate, another cast, renderer fidelity, live persistence
or Task 69 closure. A mechanically legal output whose `other` text still
describes an untyped gate action directly falsifies this transaction boundary.
